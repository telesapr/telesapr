# Audit against the definition of done

One row per feature; each column is a requirement of the definition of done below. A cell names
what meets the requirement, or says why it does not apply ("n/a" and the reason). No cell is
empty. A new feature adds its row in the commit that makes it.

## Definition of done for every new feature

A feature is done when it is tested, has a user interface and has scripting support, and the
three paths, interface, script and file, reach the same entry point in `pkg/sketch`
(`CLAUDE.md`, "Tests and the definition of done"). The order inside a feature: entry point in
`pkg/sketch`, save and load, interface, script API, path equivalence test. Document state a
feature adds goes into `UndoState` in `pkg/sketch/undo.go`, or it is lost on undo.

### Tests

| Requirement | How it is met here |
|---|---|
| Unit tests for new engine and kernel code | Beside the code. New packages hold at least 85% statement coverage and no exported function at 0% (`scripts/coverage-packages.txt`), measured with `-coverpkg=./pkg/...`, since `pkg/sketch` and `pkg/core` are mostly exercised from other packages. |
| Geometric invariants on every solid a test builds | The oracle `pkg/check`: watertight, no naked or self-intersecting edges, face count, volume and centre of mass against a closed form where one exists. |
| Golden files | A `.tlspr` fixture per feature variant under `testdata`, with a regeneration script. A golden changes only in a commit that says why. |
| Save and load round trip | Load, regenerate, save gives the same bytes. A file of the previous format version still loads. |
| Undo and redo | Every creating and editing action is one undo step and comes back identical on redo. |
| Failure behaviour | Bad input gives a diagnostic on the group, never a panic nor silently wrong geometry. Each documented failure has a test. |
| Robustness sweep, for solid features | A parameter sweep over sizes, angles and placements (`pkg/internal/sweep`), its allowed failure rate fixed before the feature starts. Fuzz targets for parsers. |
| Concurrency | `go test -race` over the touched packages; the same result on one goroutine and on eight. |
| Performance | A benchmark for anything on the regeneration path, compared with the previous commit. |
| Interface scenario | A script under `testdata/ui/scripts` that drives the feature through menus, mouse and text window on the headless platform. |
| Path equivalence | One test builds the same model through the interface and through a Go script and requires identical saved files. |

### User interface

- A menu entry in `pkg/ui/menu_table.go`, with an accelerator where one is free, and a toolbar icon for features used while drawing.
- A text-window screen showing every parameter of the feature, editable in place, with expressions wherever a number is.
- Selection-driven creation: select, then invoke; a message saying what to select when the selection does not fit.
- Feedback on the canvas: hover and selection highlighting for whatever the feature lets the user pick, and failure marked where it happened.
- An entry in the command search. No feature reachable only from the console or the command line.

### Scripting

- A method on `pkg/script/api` to create the feature, to read and change every parameter the text window shows, and to query the result.
- Doc comments on every method (`help()` and `docs.json` come from them); `make generate` run and `make generate-check` passing.
- A runnable example under `examples/scripts`, executed by a test.
- A test in `pkg/script/api` that covers misuse as well as use, as `TestMisuse` does.
- Reachable from `telesapr-cli run`, so the feature works without a window.
- Kernel foundations have no interface of their own, but expose what scripts can use.

## The audit

Where things are:

- **Scenario**: an interface script in `testdata/ui/scripts`, with its golden in
  `testdata/ui/golden/<name>.goui` (`TestGoScripts`).
- **Path pair**: `testdata/ui/scripts/path_<name>.script` and `.go`, compared by
  `TestPathEquivalence` in `pkg/ui/pathequiv_test.go`.
- **Example**: `examples/scripts/<name>`, each run by `TestExamplesRun` in `cmd/telesapr-cli`.
- **Golden**: files compared byte for byte, regenerated only by `scripts/regen-golden.sh` and
  `scripts/regen-goui.sh`. `testdata/solid/*.tlspr` are `TestSolidGoldens` in `pkg/sketch`.
- **Sweep**: a `sweep.Grid` test; its allowance is in the test ("none allowed": `MaxFailRate` 0).
  Parsers have fuzz targets instead (`make fuzz`).
- **Benchmark**: a `Benchmark*` function on the regeneration path.
- **Undo**: a test that the feature's action is one undo step that redo restores; in
  `pkg/sketch` the `undoRedo` helper compares the saved files.
- **Round trip**: save, open, save gives the same bytes; in `pkg/sketch` the `roundTrip` helper.
  `TestEveryFieldRoundTrips` in `pkg/persist/tlspr` round-trips a document that sets every field
  of the format.

## The export options a script reaches

The configuration and export-options screens set `export.Options` (canvas, margin, background,
shaded triangles, PWL curves, G-code feed, scale and offset, export chord tolerance and segment
limit); a script's export in the window, under `telesapr-cli run` and `mcp` goes through the same
writers. A script reads and sets them with `File.ExportOptions` and `File.SetExportOptions` (an
`api.ExportOptions`, checked by the screen's rules), and the display limit with
`Edit.SetMaxSegments` and `Edit.MaxSegments`, beside `Edit.SetChordTolerance`. The export tolerance
reaches the exported mesh: `ExportMeshTo` regenerates at it.

`AngleTol` (degrees, 0 for off) bounds the angle between neighbouring facets, applied by the PWL
curves, the surface grid and the CDT cells but not by marched intersection curves. `StrictMesh`
refuses an unsound mesh (`sketch.ErrMeshNotSound`). `File.SetMeshQuality` takes `api.MeshDraft`,
`api.MeshStandard` (the default) or `api.MeshFine`; `ExportOptions.Quality()` names the preset the
values match, or `MeshCustom`. `telesapr-cli export-mesh` takes `--quality`, `--angle-tol`,
`--max-segments` and `--strict`.

Tests: `TestScriptExportOptions`, `TestScriptExportMeshTolerance`, `TestScriptExportMeshQuality`
(`pkg/ui`); `TestExportOptions`, `TestExportOptionsMesh`, `TestExportStrictMesh`,
`TestSetMaxSegments` (`pkg/script/api`).

Open: a sketch opened without the application (`api.Open`, `New`) writes only STL, 3MF and glTF,
so there the 2d options are kept and returned but nothing reads them; a script run by the
application or `telesapr-cli run` is the way to a 2d file.
